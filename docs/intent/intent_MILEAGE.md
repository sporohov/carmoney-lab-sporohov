# Intent MILEAGE: проверка пробега в решении по заявке

## 1. Замысел

Добавить в расчёт решения по заявке проверку пробега авто: пробег не больше
400 000 км, иначе решение review (ответ в интервью — постановка задачи).
Сегодня решение по заявке не зависит от пробега: оно считается только по LTV
(код: backend/src/Domain/DecisionEngine.php), а пробег используется лишь при
проверке входных данных (код: backend/src/Domain/ApplicationValidator.php).

## 2. Зачем

Пробег, хотя и проверяется на входе, сегодня никак не влияет на решение —
оно зависит только от LTV (код: backend/src/Domain/DecisionEngine.php).
Проверка устраняет этот пробел: решение по заявке начинает учитывать пробег,
и заявки с пробегом больше 400 000 км уходят в review (ответ в интервью).

## 3. Constraints

- Правило: «пробег авто не больше 400 000 км, иначе решение review» —
  проверка входит именно в расчёт решения по заявке, а не в проверку входных
  данных (ответ в интервью).
- Порог: 400 000 км (ответ в интервью). Трактовка границы «не больше» —
  проходит ли ровно 400 000 км — не подтверждена, см. Open questions №1.
- Решение сегодня: LTV < 60.0 → approve; 60.0…85.0 → review; LTV > 85.0 →
  reject. Пороги 60.0 и 85.0 — код: backend/config/rules.php; ветвление —
  код: backend/src/Domain/DecisionEngine.php. На границе 60.0 код расходится
  с собственным описанием (строгая проверка вместо нестрогой) —
  код: backend/src/Domain/DecisionEngine.php; это расхождение вне задачи.
- Пробег на входе проверяется в диапазоне 0…500 000 км; при выходе за
  диапазон заявка до расчёта решения не доходит (ошибка валидации) —
  код: backend/src/Domain/ApplicationValidator.php; предел 500 000 —
  код: backend/config/rules.php. Следствие: заявки с пробегом больше 500 000 км
  до нового правила не доходят (код: backend/src/Domain/ApplicationValidator.php).
- Взаимодействие нового правила с решением по LTV не определено; буквальная
  формулировка «иначе решение review» расходится с возможным чтением «пробег
  понижает только approve» — см. Open questions №2, самостоятельно не решаем.
- Поведение для заявки без поля пробега в постановке не оговорено; сегодня
  такая заявка — ошибка валидации (код: backend/src/Domain/ApplicationValidator.php);
  см. Open questions №3.

## 4. Open questions

1. Граница порога: проходит ли ровно 400 000 км без понижения или уже даёт
   review. Статус: открыт — в интервью ответ «не знаю»; формулировка «не
   больше 400 000 км» допускает включительное чтение, но подтверждения нет.
2. Приоритет с решением по LTV: что вернуть, если LTV даёт reject, а пробег
   больше 400 000 км; и остаётся ли review по LTV при высоком пробеге.
   Статус: открыт — в интервью ответ «не знаю»; буквальная формулировка
   «иначе решение review» допускает чтение «решение заменяется на review»,
   что расходится с чтением «понижает только approve».
3. Заявка без пробега: сохранять ли текущее поведение — ошибка валидации
   (код: backend/src/Domain/ApplicationValidator.php). Статус: открыт — в
   интервью ответ «не знаю».
4. Границы задачи (что вне scope). Статус: закрыт — заказчик, ответ в
   интервью «как в плане»; результат — в разделе «Не входит».

## 5. Не входит

Ответ в интервью — выбор «как в плане»:

- проверка входных данных и её предел 500 000 км (код: backend/config/rules.php);
- пороги решения по LTV 60.0 / 85.0 (код: backend/config/rules.php) и
  существующее расхождение кода и описания на границе 60.0
  (код: backend/src/Domain/DecisionEngine.php);
- фронтенд;
- база данных и миграции;
- задача LOAN-12 — лимит по возрасту авто (справочник ltv_by_age,
  код: backend/config/rules.php).
